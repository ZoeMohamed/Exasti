## 1. Untuk siapa ini dirancang

**Bu Sri, 45 tahun.** Warung ayam geprek di Tembalang, 8 menu.

```
Perangkat     Android, layar retak, mengetik satu jari
Konteks       sore hari, warung sepi sebentar, bisa diinterupsi pembeli
Kebiasaan     mencatat belanja di buku tulis
Kosakata      bilang "untung" dan "balik modal" — TIDAK bilang "margin"
Matematika    tahu "2 kilo jadi 8 porsi". TIDAK tahu "0,25 kg per porsi".
Waktu luang   sekitar 10 menit, terputus-putus
```

**Bu Sri tidak akan membaca tutorial, tidak akan menonton video onboarding,
dan tidak akan mencoba dua kali kalau percobaan pertama membingungkan.**

Pengguna kedua: **Rian, 22 tahun**, anaknya. Dia yang memasang dan mengisi data
awal. Boleh sedikit lebih sabar dengan form — tapi pemakaian harian harus
cukup untuk Bu Sri sendirian.

## 2. Prinsip penulisan teks

Ini bagian yang paling sering dirusak desainer. Ikuti ketat.

| Jangan tulis | Tulis |
|---|---|
| Margin 17,1% | **Untung Rp 3.085 per porsi** (17%) |
| HPP | **Modal** |
| Harga Pokok Produksi | **Modal per porsi** |
| Komoditas | **Bahan** |
| Ingest / sinkronisasi | **Harga hari ini sudah masuk** |
| Severity: critical | **Perlu segera dicek** |
| Takaran 0,25 kg | **2 kg untuk 8 porsi** |
| Anda | **Kamu** |

**Aturan angka:** rupiah selalu lebih dulu, persen jadi pelengkap dalam kurung.
Bu Sri merasakan rupiah; persen itu abstrak.

```
✅  Untung Rp 3.085 per porsi (17%)
❌  Margin 17,1%
```

**Aturan kalimat:** satu kalimat, satu gagasan. Tidak ada anak kalimat.

```
✅  "Untung ayam gepekmu turun separuh."
❌  "Terdeteksi penurunan margin sebesar 10,1 poin persentase pada item menu
     Ayam Geprek yang disebabkan oleh kenaikan harga komoditas daging ayam."
```

## 3. Keputusan desain dan alasannya

Empat keputusan ini lahir dari simulasi di §8. Jangan dibatalkan tanpa membaca itu.

### 3.1 Tanya sekali masak, bukan per porsi

**Jangan pernah** meminta pengguna menghitung takaran per porsi.

```
❌  "Takaran ayam (kg)"  →  Bu Sri harus membagi 2 ÷ 8 di kepala
✅  "Sekali masak habis 2 kg ayam"  +  "Jadi 8 porsi"
```

Sistem yang membagi. Dan saat pengguna mengedit nanti, **tampilkan kembali
angka aslinya** — "2 kg, 8 porsi" — bukan 0,25.

### 3.2 Satu menu dulu, bukan delapan

Onboarding hanya meminta **satu menu — yang paling laku.** Menu lain ditawarkan
belakangan, setelah alert pertama mendarat dan terasa berguna.

### 3.3 Tunda semua yang bukan jalan menuju angka pertama

Gas, kemasan, bumbu **tidak ditanyakan** saat menu pertama. Sistem memberi
perkiraan dan menandainya terbuka:

> Gas + kemasan kami kira **Rp 1.200 per porsi**. Bisa kamu betulkan nanti.

### 3.4 Template, bukan halaman kosong

Pengguna memilih jenis warung, takaran umum sudah terisi, dia tinggal
**mengoreksi**. Mengetik dari nol adalah penyebab utama orang berhenti.

## 5. Layar kunci, terperinci

### S5 · Hasil pertama — layar terpenting di seluruh produk

Ini momen yang menentukan apakah Bu Sri kembali atau tidak. Muncul **≤2 menit**
setelah dia mulai.

```
┌──────────────────────────────────────────┐
│                                          │
│   Ayam Geprek                            │
│                                          │
│   Untungmu                               │
│   Rp 3.085                               │
│   per porsi                              │
│                                          │
│   Modal Rp 14.915  ·  Jual Rp 18.000     │
│                                          │
│   ─────────────────────────────────────  │
│   92% harga dari data Bank Indonesia     │
│   Gas + kemasan kami kira Rp 1.200 —     │
│   bisa kamu betulkan nanti               │
│                                          │
│   [ Tambah menu lain ]   [ Nanti saja ]  │
│                                          │
└──────────────────────────────────────────┘
```

Catatan desain:
- **Rp 3.085 adalah elemen terbesar di layar.** Semua yang lain pendukung.
- "Nanti saja" bukan pilihan kelas dua — banyak pengguna berhenti di satu menu,
  dan itu tidak apa-apa.
- Baris sumber data selalu tampil. Transparansi ini yang membuat angkanya dipercaya.

### S6 · Dashboard

Terurut dari untung **terkecil** — yang bermasalah selalu di atas.

```
┌──────────────────────────────────────────┐
│  Warung Bu Sri          11 Sep 2026      │
│  Harga hari ini sudah masuk ✓            │
│                                          │
│  ⚠ Ayam Geprek                           │
│    ███░░░░░░░  Rp 1.260   turun dari     │
│                (7%)       Rp 3.085       │
│                                          │
│  ✓ Nasi Goreng                           │
│    ██████░░░░  Rp 3.600   tetap          │
│                (24%)                     │
│                                          │
│  ✓ Es Teh Manis                          │
│    █████████░  Rp 2.740   tetap          │
│                (68%)                     │
└──────────────────────────────────────────┘
```

**Status tidak boleh bergantung warna saja** (NFR-09). Tiap baris punya tiga
penanda sekaligus: ikon (⚠ / ✓), panjang bar, dan angka rupiah.

### S7 · Detail menu — tempat pembeda produk terlihat

```
┌──────────────────────────────────────────┐
│  Ayam Geprek                             │
│                                          │
│  Untung  Rp 3.085  →  Rp 1.260           │
│  ▁▂▂▃▃▄▅▇  30 hari terakhir              │
│                                          │
│  ┌────────────────────────────────────┐  │
│  │ Gara-gara                          │  │
│  │ Daging ayam naik 20%               │  │
│  │ (65% dari modal menu ini)          │  │
│  │                                    │  │
│  │ Bukan cabai — cabai memang naik    │  │
│  │ 58%, tapi di menumu cuma 9% modal  │  │
│  └────────────────────────────────────┘  │
│                                          │
│  Kalau mau balik seperti dulu:           │
│  jual Rp 20.000                          │
│  [ Ubah harga jual ]                     │
│                                          │
│  Rincian modal ▾                         │
│   Ayam        2 kg → 8 porsi   Rp 10.950 │
│   Beras     1,2 kg             Rp  2.265 │
│   Cabai rawit 120 g            Rp  1.305 │
│   ...                                    │
│   Gas+kemasan (perkiraan)      Rp  1.200 │
└──────────────────────────────────────────┘
```

**Blok "Gara-gara" adalah alasan produk ini ada.** Beri ruang. Jangan diperkecil
jadi label kecil di pojok.

Perhatikan baris "Bukan cabai" — kontras itulah pesannya. Tanpa kalimat kedua,
ini cuma aplikasi harga pangan biasa.

Rincian modal menampilkan **"2 kg → 8 porsi"**, angka yang dia masukkan sendiri.

```

  Rp 36.500  ──────●──────────  Rp 60.000
```

## 6. Alur

### Onboarding — target ≤2 menit

```
S1  "Warungmu di mana?"          → pilih kabupaten        1 ketuk
S2  "Warungmu jual apa?"         → [Ayam Geprek] [Soto]…  1 ketuk
S3  "Jual berapa seporsi?"       → 18000                  1 ketikan
S4  "Sekali masak habis apa?"    → takaran sudah terisi,
                                    tinggal dikoreksi      ~3 koreksi
    "Jadi berapa porsi?"         → sudah terisi 8
S5  🎯 "Untungmu Rp 3.085/porsi"
```

Kalau template tidak cocok → **"Lainnya"** → isi manual, atau foto nota (S11).

### Pemakaian harian — target ≤2 menit

```
Notifikasi → S6 dashboard → ketuk yang merah → S7 detail
  → ubah harga jual  ATAU  tandai sudah dibaca
```

### Jalur sistem — pengguna tidak melihat apa pun

```
13:30 tarik harga → hitung ulang → bandingkan 7 hari
      → tentukan pendorong (BR-04) → buat alert → notifikasi
```

## 7. Aksesibilitas — bukan opsional

Rubrik EXASTI menilai inklusivitas di bagian UI/UX. Ini yang wajib:

```
NFR-07   berfungsi penuh di lebar 375 px, tanpa gulir horizontal
NFR-08   kontras teks ≥ 4,5:1 (WCAG 2.1 AA)
NFR-09   status TIDAK PERNAH disampaikan lewat warna saja
NFR-10   target sentuh minimal 44 × 44 px
NFR-12   setiap keadaan kosong menjelaskan langkah berikutnya
```

Bu Sri 45 tahun, layarnya retak, dan sering memakai HP di bawah sinar matahari.
Perlakukan teks kecil dan kontras rendah sebagai kerusakan, bukan gaya.

**Selisihnya bukan jumlah layar. Selisihnya adalah satuan yang ditanyakan.**

## 9. Friksi yang belum terpecahkan

Jujur — ini tidak semuanya selesai, dan desainer harus tahu:

| Friksi | Parah | Arah solusi |
|---|---|---|
| Menu kedua mungkin tidak pernah ditambahkan | 🔴 tinggi | Tawarkan **setelah** alert pertama terasa berguna, bukan saat onboarding |
| Template tidak cocok resepnya | 🟡 sedang | Jalur "Lainnya" harus semulus jalur template |
| Tidak yakin hasil berapa porsi | 🟡 sedang | Terima kisaran: "7–9 porsi" |
| Perkiraan gas/kemasan meleset jauh | 🟡 sedang | Ingatkan di hari ke-7, jangan di hari pertama |
| Harga jual berubah, lupa memberi tahu | 🟡 sedang | Tanya sebulan sekali |

Yang merah itu risiko produk terbesar setelah onboarding. Belum ada jawaban
yang memuaskan — kalau desainer punya ide, itu kontribusi nyata.

## 10. Yang jangan dilakukan

```
❌  Tur produk multi-langkah sebelum pengguna melihat nilai apa pun
❌  Dasbor penuh grafik di layar pertama
❌  Kata "margin", "HPP", "komoditas" di antarmuka
❌  Meminta takaran per porsi
❌  Meminta semua menu sebelum menampilkan hasil apa pun
❌  Status yang hanya dibedakan warna
❌  Menyembunyikan bahwa sebagian angka adalah perkiraan
❌  Menyebut datanya "real-time" — BI terbit sekali per hari kerja
```

Yang terakhir berlaku untuk teks antarmuka maupun materi presentasi.
